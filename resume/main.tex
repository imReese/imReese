\cvsection{独立系统项目}
独立开展推理运行时、状态复用系统和推理控制面的设计与实现。\par
\project{SGLang Rust Runtime}{2026.05 - 至今}{\href{https://github.com/imReese/sglang-rs}{github.com/imReese/sglang-rs}}{Rust / gRPC / CUDA}
\begin{itemize}
\item \lead{批次调度}按未缓存 token 数控制 Prefill 批次规模，支持页对齐的前缀复用；P/D 分离模式下，Decode 等待 KV 就绪后执行，异步 Prefill 的缓存页在传输完成后才对外可用。
\item \lead{统一物理 KV 页}CUDA 执行与 Mooncake 注册共用同一 page-major KV pool，通过 RAII 管理注册和设备内存，确保先注销再释放；失败时回收尚未对外提供的缓存页，请求取消时同步取消相关传输。
\item \lead{执行后端}实现 Qwen2/3 共享 dense decoder、F32 CPU 参考与 BF16 CUDA 执行路径，接入 cuBLAS GEMM 与 GQA paged attention。
\end{itemize}
\vspace{5pt}

\begin{itemize}
\item \lead{缓存复用判断}设计跨引擎的状态复用方案：命中后检查租户、模型版本和数据布局是否匹配，再评估复用范围、传输成本及引擎的使用条件，并记录判断依据。
\item \lead{引擎与存储解耦}设计统一的状态描述和复用接口，将复用判断与存储、传输分开；由推理引擎决定是否使用外部缓存并负责内存分配，便于接入不同引擎和存储后端。
\item \lead{索引与引擎适配}使用 Rust 实现前缀匹配和写时复制索引，构建 Host DRAM 存储；通过引擎适配接口协调状态传输、使用与释放。
